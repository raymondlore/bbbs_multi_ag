# AI 과제 등록 게시판 MVP 계획

작성: 리더가 팀원 3명(ux, architect, critic)의 토론 결과를 통합. 이번 단계는 계획만 다루며 코드는 없다. 초안 원본은 `docs/drafts/`에 있다. API 계약은 `docs/api.md`를 따른다.

## 1. 기능 범위
**포함**
- 과제 등록: 과제명, 설명, 배포 URL / 저장소 URL(최소 1개 필수), 작성자, 태그(최대 5개), 스크린샷 1장(선택)
- 과제 목록: 최신순, 20개 단위 페이지네이션, 태그 필터(단일 선택), 키워드 검색(과제명·설명)
- 과제 상세: 전체 정보와 스크린샷
- 과제 수정·삭제: 서버가 등록 시 발급한 수정용 비밀번호로 처리

**제외(2차 확장)**
- 로그인/SSO, 댓글, 좋아요, 관리자 화면
- 복수 태그 AND 필터, 조회수, 다크모드, 임시저장, 마크다운
- 썸네일 생성, FTS5 전문 검색, 비밀번호 재발급, PATCH, 멱등키

## 2. 화면 흐름
화면은 목록, 등록·수정(같은 폼 재사용), 상세 3개이고, 등록 직후에 비밀번호 안내가 한 번 나온다. 해시 라우팅을 쓴다.

`목록(#/)` → `등록(#/new)` → `비밀번호 안내` → `상세(#/projects/{id})` → `수정(#/projects/{id}/edit)` 또는 `삭제(확인 다이얼로그)`

목록 상태는 URL에 보존한다(`#/?q=&tag=&page=`). 그래서 뒤로가기와 필터 유지가 된다.

### 목록
- 구성: 제목, [과제 등록], 검색 입력, 태그 칩 필터(`GET /tags`, 단일 선택, 재클릭으로 해제), 항목(제목, 요약 150자, 작성자, 태그 칩, 등록일, 썸네일), 페이지네이션(이전/다음, 번호 최대 5개, 총 건수)
- 이미지가 없으면 인라인 SVG로 대체한다. 검색·필터를 바꾸면 page=1로 돌아간다.
- 상태: 로딩, 빈 목록(첫 등록 유도), 결과 없음(필터 초기화), 오류(재시도)

### 등록·수정(같은 폼)
- 필드: 과제명*, 설명*(글자수 표시), 배포 URL / 저장소 URL("둘 중 하나 이상" 안내), 작성자*, 태그(엔터/콤마로 칩 추가), 스크린샷(미리보기, 제거)
- 클라이언트 검증은 편의용이고 최종 검증은 서버다. 제출 중에는 버튼을 비활성화하고, 실패해도 입력값은 유지한다.
- 수정 모드: 기존값 프리필, 스크린샷 유지/교체/제거, 폼 하단의 수정용 비밀번호 입력란(`type=password`). PUT은 전체 교체라서 폼에서 지운 URL·태그는 삭제된다.
- 413/415는 스크린샷 필드 옆에 표시한다.

### 비밀번호 안내(등록 201 직후)
- 비밀번호 표시와 [복사] 버튼(실패 시 선택 가능한 읽기 전용 입력으로 대체), "다시 볼 수 없고 분실 시 수정·삭제 불가" 경고
- "보관했습니다" 체크 후 [상세 보기]가 활성화된다. 비밀번호는 JS 메모리에만 두고 URL·localStorage·sessionStorage에 저장하지 않는다. 새로고침하면 사라진다.

### 상세
- 전체 정보와 스크린샷(없으면 영역 숨김), 링크는 새 탭(`rel="noopener noreferrer"`)으로 열고 http/https만 링크로 만든다. 없는 링크 줄은 숨긴다.
- [수정] [삭제] [목록으로]. 삭제는 확인 다이얼로그에서 비밀번호를 입력받아 바로 DELETE하며, 403이면 다이얼로그를 유지하고 재입력을 허용한다.
- 상태: 로딩, 404(삭제되었거나 없음), 오류

### 비밀번호 오류 문구
401 "비밀번호를 입력하세요" / 403 "비밀번호가 일치하지 않습니다"(남은 횟수 표시 없음) / 429 "잠시 후(약 15분) 다시 시도"(`Retry-After`가 있으면 분 단위로 표시, 입력 일시 비활성)

## 3. 결정 사항
1. 태그 필터는 단일 선택(`?tag=` 1개). 복수 AND는 2차.
2. API 경로는 `/api/v1/projects`, 화면 문구는 "과제"로 통일.
3. 수정용 비밀번호는 서버가 발급하며 등록 응답에서 한 번만 보여 준다. 사용자 지정은 없다.
4. 비밀번호는 저장·삭제 요청 시점에만 검증한다. 수정 화면 진입은 자유이고, 사전 확인 API(`/verify`)는 두지 않는다.
5. 수정은 PUT 전체 교체. 이미지는 첨부 시 교체, `remove_image=true`면 삭제.
6. 배포 URL과 저장소 URL 중 최소 1개 필수. 태그는 최대 5개(각 20자).
7. `GET /tags`는 유지한다(태그 칩 소스).
8. 429 락아웃은 MVP에 포함한다(연속 실패 5회, 15분, `(과제, IP)` 키, 프로세스 메모리). critic의 제외 권고는 이견으로 남기고, 리더가 포함으로 결정했다.
9. 새 라이브러리 `python-multipart`(파일 업로드 파싱용)를 승인한다. `requirements.txt`에 `==`로 버전 고정하고 wheelhouse에 포함한다. 구현 시점에 설치 가능한 최신 안정 버전을 확정한다.
10. 검색은 `LIKE`(`%`, `_`, `\` 이스케이프)로 하고 FTS5는 제외한다. 썸네일은 만들지 않고 원본을 CSS로 축소한다.
11. 스크린샷은 `data/uploads/`(웹 루트 밖)에 `uuid4hex+확장자`로 저장하고 API로만 제공한다(StaticFiles 마운트 안 함). png/jpg/webp, 2MB, 확장자와 매직 바이트 모두 검사.
12. 검증 실패는 HTTP 422 + `VALIDATION_ERROR`로 통일한다(FastAPI 기본 상태 코드 유지, 본문만 오류 형식으로 변환). 화면은 422의 `error.message`를 폼 상단에 표시한다.
13. 사내 http 환경에서 비밀번호가 평문으로 전송되는 점은 MVP에서 수용한다. 위험 요소로 기록하고, 리버스 프록시 TLS를 배포 단계에서 권고한다.

### 추가 결정 (구현 전 보완)
- **잠금 우선:** 잠금 상태이면 비밀번호 정답 여부와 관계없이 429를 반환한다.
- **PUT 충돌 규칙:** `image`와 `remove_image=true`가 함께 오면 422 `VALIDATION_ERROR`.
- **입력 정규화:** 모든 텍스트 필드와 `tags` 항목은 trim 후 빈 문자열이면 미입력으로 간주한다.
- **본문 크기:** 요청 본문 전체가 3MB(`Content-Length` 기준)를 넘으면 413 `REQUEST_TOO_LARGE`. 이미지 2MB 초과의 `IMAGE_TOO_LARGE`와 구분한다.
- **프록시:** `X-Forwarded-For`는 기본 불신, 환경변수 `TRUST_PROXY=1`일 때만 사용한다.
- **CSP와 스타일:** CSP 때문에 인라인 `style` 속성과 `<style>` 블록을 금지하고 외부 CSS 파일만 쓴다(인라인 script/onclick 금지와 같은 원칙).
- **테스트 지원(tester 메모):** 락아웃 카운터를 테스트마다 초기화할 수 있는 함수(예: `reset_lockout()`)를 `api/` 코드에 둔다. HTTP 엔드포인트로는 노출하지 않는다.

## 4. DB 설계 요약
- `projects(id, title, description, deploy_url, repo_url, author, password_hash, image_filename, created_at, updated_at)`
- `tags(id, name UNIQUE NOCASE)`, `project_tags(project_id, tag_id)` (ON DELETE CASCADE)
- 인덱스: `projects(created_at DESC, id DESC)`, `project_tags(tag_id, project_id)`
- 고아 태그는 삭제 시 정리한다. 스키마 전문은 `docs/drafts/architect.md` §1 참고.
- 연결은 요청마다 만들고, 연결마다 `foreign_keys=ON`, `busy_timeout=5000`, WAL을 설정한다.

## 5. 보안 요구
- SQL은 전부 파라미터 바인딩. 사용자 입력은 화면에 `textContent`로만 넣는다(innerHTML 금지). 인라인 script/onclick 금지.
- 링크 URL은 서버(urlparse로 http/https + netloc, 제어문자 거부)와 클라이언트(`new URL` protocol 검사)에서 이중 검증한다.
- 비밀번호는 PBKDF2-HMAC-SHA256 12만 회와 salt로 저장하고, `hmac.compare_digest`로 비교한다. 해시 검증은 `def` 핸들러(스레드풀)로 처리해 이벤트 루프를 막지 않는다.
- 비밀번호는 헤더(`X-Edit-Password`)로만 전달한다. 리버스 프록시를 쓰면 헤더 로깅을 금지한다.
- 보안 헤더(CSP, nosniff)를 적용하고, 오류 응답에 스택 등 내부 정보를 노출하지 않는다. CORS는 동일 출처라 설정하지 않는다(와일드카드 금지).
- 업로드는 본문을 읽는 도중 2MB+1B에서 중단한다. 저장 순서는 새 파일 저장 → DB 커밋 → 이전 파일 삭제이고, 실패 시 새 파일을 정리한다.

## 6. 폐쇄망 배포 요구
- CDN, 외부 폰트, 외부 아이콘, 외부 API 금지. 시스템 폰트 스택과 인라인 SVG를 쓴다.
- FastAPI 자동 문서(`/docs`, `/redoc`)는 CDN을 쓰므로 비활성화한다(`docs_url=None, redoc_url=None`). 계약서는 `docs/api.md`가 대신한다.
- 표준 `sqlite3`, `hashlib`, `secrets`, `hmac`만 쓴다. 의존성은 wheelhouse(`pip download -d wheelhouse` 후 `pip install --no-index --find-links`)로 반입한다.
- 데이터 경로는 환경변수 `DATA_DIR`(기본 `./data`). 백업은 `sqlite3 .backup`과 `uploads/`를 함께 보관한다.
- uvicorn 워커는 1개로 고정한다(429 카운터 때문). 라우터는 `/api`를 먼저 등록하고 그다음 `StaticFiles(web, html=True)`를 마운트한다.
- 클립보드 API는 http 환경에서 막힐 수 있어 선택 가능한 입력창을 폴백으로 둔다.

## 7. 알려진 한계·위험
- 비밀번호를 분실하면 복구할 수 없다. 운영자가 DB에서 직접 처리하고, 관리자 화면은 2차다.
- 429 카운터는 재시작하면 초기화되고, 다중 워커에서는 무력하다. 비밀번호가 약 70bit 무작위라 온라인 추측은 비현실적이어서 실효는 낮다(critic이 제외를 권했으나 리더 결정으로 유지).
- 프록시 뒤에서 `TRUST_PROXY`를 켜지 않으면 모든 사용자가 프록시의 공용 IP 하나로 보인다. 이때 누군가 비밀번호를 5회 틀리면 같은 과제를 쓰는 다른 사용자도 15분간 잠기는 잠금 DoS가 생긴다. 반대로 `TRUST_PROXY=1`을 신뢰할 수 없는 환경에서 켜면 헤더를 위조해 잠금을 피할 수 있다. 배포 환경에 맞춰 설정을 정한다.
- 원본 이미지(최대 2MB)를 썸네일로 쓰므로 목록 로딩 부담이 클 수 있다. `loading="lazy"`로 완화하고, 심하면 2차에서 처리한다.
- 비밀번호는 사내 http에서 평문으로 전송된다(결정 12).
