# E2E 시나리오 5: 오류 상태와 비밀번호 잠금

기준: `docs/plan.md` 2절 '비밀번호 오류 문구', `docs/api.md` 6절. 사전 조건: 과제 1건과 올바른 비밀번호 `PW`. 서버는 `TRUST_PROXY` 없이 실행(모든 접속이 같은 IP). 각 시나리오 전에 서버를 재시작하면 잠금이 초기화된다.

| # | 단계 | 기대 결과 | 결과 |
|---|---|---|---|
| 1 | 삭제 다이얼로그(또는 수정 저장)에서 틀린 비밀번호를 4회 입력 | 매번 "비밀번호가 일치하지 않습니다", 남은 횟수는 표시되지 않음 | |
| 2 | 5회째 틀린 비밀번호 입력 | 여전히 403 문구(5번째 실패까지는 일치 오류) | |
| 3 | 6번째 시도(틀린 값) | "잠시 후(약 15분) 다시 시도" 문구(429), 가능하면 분 단위 표시, 입력란·버튼이 일시 비활성 | |
| 4 | 잠금 중 올바른 `PW`로 삭제·수정 시도 | 정답이어도 429 문구가 나오고 과제는 삭제·수정되지 않음 | |
| 5 | 다른 과제에서 올바른 비밀번호로 수정 | 해당 과제는 잠기지 않아 정상 저장 | |
| 6 | 서버 재시작 후 같은 과제에 `PW`로 삭제 | 잠금이 풀려 삭제 성공(카운터는 메모리 방식) | |
| 7 | 4회 틀린 뒤 올바른 `PW`로 수정 성공, 이후 다시 4회 틀림 | 성공 시 카운터가 초기화되어 잠기지 않음 | |
| 8 | 존재하지 않는 과제 id(`#/projects/99999/edit`)에서 저장 | 404 안내 | |
| 9 | 설명 2001자·제목 101자로 등록 | 해당 필드명이 포함된 422 메시지가 폼 상단에 표시 | |
| 10 | 존재하지 않는 해시 경로(`#/abc`) 접속 | 빈 화면이 아니라 안내 또는 목록으로 이동 | |
| 11 | `http://localhost:8000/docs`, `/openapi.json` 접속 | 404(문서 화면 없음), 본문은 오류 JSON | |
| 12 | `http://localhost:8000/api/v1/nope` 접속 | `{"error": {"code": "NOT_FOUND", ...}}` JSON | |
| 13 | 개발자도구 콘솔·네트워크 확인 | CSP 위반 경고 없음, 외부 도메인 요청 없음(폰트·CDN 포함) | |
| 14 | 네트워크 차단(서버 중지) 상태에서 저장·삭제 | 입력값 유지된 채 오류 토스트/메시지 표시, 버튼 재활성화 | |
