# E2E 시나리오 1: 목록·검색·태그 필터·페이지네이션

기준: `docs/plan.md` 2절 '목록'. 사전 조건: 서버 실행(`uvicorn api.main:app --workers 1`), 브라우저로 `http://localhost:8000/#/` 접속. 과제 25건 이상 등록(태그 `챗봇`, `RAG` 포함), 그중 일부는 스크린샷 없음.

| # | 단계 | 기대 결과 | 결과 |
|---|---|---|---|
| 1 | 빈 DB 상태에서 `#/` 접속 | "아직 등록된 과제가 없습니다" 류의 빈 목록 안내와 첫 등록 유도 버튼 표시 | |
| 2 | 로딩 중 확인(개발자도구에서 네트워크 느리게) | 로딩 표시 후 목록으로 교체 | |
| 3 | 과제 25건 등록 후 목록 접속 | 최신 등록순으로 20개 표시, 카드에 제목·요약(150자)·작성자·태그 칩·등록일·썸네일 | |
| 4 | 스크린샷 없는 과제 확인 | 인라인 SVG 대체 이미지 표시 | |
| 5 | 하단 페이지네이션 확인 | 총 건수, 이전/다음, 번호(최대 5개) 표시. 1페이지에서 '이전' 비활성 | |
| 6 | 2페이지 클릭 | 나머지 5건 표시, URL이 `#/?page=2`로 변경, 마지막 페이지에서 '다음' 비활성 | |
| 7 | 브라우저 뒤로가기 | 1페이지로 복귀 | |
| 8 | 검색창에 과제명 일부 입력 후 검색 | 제목·설명에 포함된 과제만 표시, URL에 `q=` 반영, page=1로 복귀 | |
| 9 | `%` 또는 `_` 만 입력해 검색 | 와일드카드가 아니라 해당 문자가 실제 들어간 과제만 표시(없으면 '결과 없음') | |
| 10 | 존재하지 않는 단어 검색 | '결과 없음' 상태와 필터 초기화 버튼 표시 | |
| 11 | 101자 이상 입력 | 입력 제한 또는 오류 안내(서버 422 시 메시지 표시) | |
| 12 | 태그 칩 `챗봇` 클릭 | 해당 태그 과제만 표시, 칩 강조, URL에 `tag=` 반영 | |
| 13 | 다른 태그 칩 클릭 | 단일 선택이므로 이전 선택이 해제되고 새 태그만 적용 | |
| 14 | 선택된 칩을 다시 클릭 | 필터 해제, 전체 목록 복귀 | |
| 15 | 검색어 + 태그 동시 적용 | 두 조건을 모두 만족하는 과제만 표시 | |
| 16 | 필터가 적용된 URL을 새로고침/새 탭에 붙여넣기 | 같은 검색·필터·페이지 상태 복원 | |
| 17 | 제목에 `<script>alert(1)</script>`가 든 과제 확인 | 경고창 없이 문자 그대로 표시 | |
| 18 | 서버를 중지한 뒤 새로고침 | 오류 상태와 [재시도] 버튼. 서버 재시작 후 재시도하면 정상 표시 | |
| 19 | 브라우저 폭을 모바일(375px)·태블릿(768px)으로 축소 | 가로 스크롤 없이 카드가 재배치됨 | |
| 20 | Tab 키로 이동 | 검색창, 칩, 카드, 페이지 버튼에 포커스 표시가 보임 | |
