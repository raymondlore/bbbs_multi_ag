# E2E 시나리오 4: 수정·삭제

기준: `docs/plan.md` 2절 '등록·수정', '상세', '비밀번호 오류 문구'. 사전 조건: 스크린샷·태그 2개·URL 2개가 있는 과제와 등록 시 받은 비밀번호(`PW`)를 알고 있다.

| # | 단계 | 기대 결과 | 결과 |
|---|---|---|---|
| 1 | 상세에서 [수정] 클릭 | `#/projects/{id}/edit`에 기존값이 프리필됨(태그 칩, 스크린샷 미리보기 포함), 하단에 수정용 비밀번호 입력란(`type=password`) | |
| 2 | 비밀번호 비워 두고 저장 | "비밀번호를 입력하세요"(401) | |
| 3 | 틀린 비밀번호로 저장 | "비밀번호가 일치하지 않습니다"(403), 남은 횟수 표시 없음, 입력값 유지 | |
| 4 | 제목 변경 후 올바른 `PW`로 저장 | 상세로 이동하고 새 제목 표시, 등록일은 그대로 | |
| 5 | 수정 화면에서 배포 URL을 지우고 저장 | 저장소 URL만 남음(전체 교체), 둘 다 지우면 URL 오류 | |
| 6 | 태그 하나 제거 후 저장 | 상세와 목록의 태그가 줄어듦, 더 안 쓰이는 태그는 목록 태그 칩에서 사라짐 | |
| 7 | 스크린샷 교체 후 저장 | 새 이미지 표시(브라우저 캐시에 옛 이미지가 남지 않음) | |
| 8 | 스크린샷 제거 후 저장 | 상세에서 스크린샷 영역 숨김, 목록은 SVG 대체 이미지 | |
| 9 | 수정 화면 URL을 직접 열고(새로고침) 확인 | 기존값 다시 프리필, 비밀번호란은 비어 있음 | |
| 10 | 상세에서 [삭제] 클릭 | 확인 다이얼로그에 비밀번호 입력란 표시 | |
| 11 | 틀린 비밀번호로 삭제 | 다이얼로그 유지, 403 문구 표시, 재입력 가능 | |
| 12 | 올바른 `PW`로 삭제 | 목록으로 이동, 해당 과제가 사라짐, 상세 URL 재접속 시 404 상태 | |
| 13 | 다이얼로그 취소/Esc | 닫히고 과제는 그대로 | |
| 14 | 삭제된 과제의 수정 URL 접속 후 저장 | 404 안내 | |
| 15 | 다이얼로그에서 Tab 이동 | 포커스가 다이얼로그 안에서 이동하고 닫으면 원래 버튼으로 복귀 | |
